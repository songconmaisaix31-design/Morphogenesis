# T2 execution runtime

## Scope and API handoff

Only `orchestration/**`, `tests/t2/**`, and this file are owned by T2.
Merged dependencies: T0 `64064c3`, topology `a12d288`, metabolism `240aaf0`,
fixed provision `1c4e5e9`. Public contracts are imported, never duplicated.

`orchestration.events.export_events(store: EventStore, run_id: str,
destination: str | Path) -> int` writes a UTF-8 JSONL snapshot of full Envelope
objects ordered by `(seq, msg_id)`. It returns the event count and does not
change handled/provenance/acceptance. T5 can read each line with
`Envelope.model_validate_json(line)`. Store construction belongs to T0;
visualization does not require LangGraph imports.

Implemented graph: select/inject -> execute -> independent verify -> feedback.
Use `SqliteSaver.from_conn_string` as a context manager and `thread_id` for
restart. Persist an execution intent using T0 EventStore *before* calling CLI;
if this node replays with an existing intent, conservatively block rather than
repeat an uncertain external action. This is not an exactly-once claim.

## Reuse and execution boundary

- Installed public CLI: `codex-cli 0.155.1`; local `codex exec --help` confirms
  `--sandbox read-only`, `--json`, `--output-schema`, `--output-last-message`,
  `--ephemeral`, `--ignore-user-config`. Upstream Apache-2.0; no source copied.
- [Codex noninteractive documentation](https://developers.openai.com/codex/noninteractive)
  is supplemental to the installed help. The CLI produces structured proposals;
  a narrow adapter applies only the fixed `sample.py` artifact. Tests remain
  outside the task workspace. No sandbox bypass option is used.
- [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence):
  official StateGraph and SQLite checkpointer, MIT. T0 owns dependency locking.
  Checkpoints store graph state, not OS processes or filesystem transactions.
- Independent review uses T0's fixed SampleVerifier and a distinct reviewer
  identity, requiring no second model call. This is deterministic verification,
  not a claim of a second model reasoning about the repair.

## Concrete APIs and commands

- `orchestration.codex.CodexExecutor(evidence_dir, model=..., stop_requested=...)`
  implements T0 Executor. It uses the public CLI in read-only mode with shell,
  subagent, plugin, hook, browser and computer tools disabled. Input comes through
  a file-backed stdin; output is a Pydantic structured Proposal, not commands.
- `task_workspace` permits only an isolated OS-temp task root containing the two
  fixed input files, with only `sample.py` writable; links/extra files/oversized
  inputs reject. `sample_policy.validate_sample` is a conservative pure-function
  syntax restriction for this exercise, not a general Python/OS sandbox.
- `Runtime(config,saver,events,results,topology,metabolism,executor,verifier,
  members,reviewer,...)`: `start(task_id)`, `resume()`. Saver must remain inside
  `with SqliteSaver.from_conn_string(path)`. Optional callbacks connect T3's
  bind_attempt, explicit adoption reader and message-aware topology feedback.
- The runtime has one task and at most one CLI admission per run. A durable
  execution intent is written before launch using T0's existing EventStore.
  Runtime does not schedule retries, so configured retry/no-progress round
  maxima are upper bounds; it stops after the first terminal result. Adapter
  additionally enforces wall timeout, inactivity timeout, and a manual stop
  callback. The executable entry uses a `STOP` file under its evidence root.
- `orchestration.acceptance` is an explicit single-run diagnostic entry, not a
  campaign scheduler. `--experience` consumes a previous verified run and its
  reviewed feedback. FixedProvisioner supplies five logical members; it does
  not launch ORCA agents. A continuation only resumes the existing graph.

From this worktree's installed Poetry environment (each fresh command consumes
one model call; **do not rerun these paid examples automatically**):

```powershell
poetry run python -m orchestration.acceptance --root "$env:TEMP/morph-t2-normal-20260922" --model gpt-5.6-luna --timeout 180
poetry run python -m orchestration.acceptance --root "$env:TEMP/morph-t2-resume-20260922" --model gpt-5.6-luna --pause-after-execute --timeout 180
poetry run python -m orchestration.acceptance --root "$env:TEMP/morph-t2-resume-20260922" --continue
poetry run python -m orchestration.acceptance --root "$env:TEMP/morph-t2-reuse-20260922" --model gpt-5.6-luna --experience "$env:TEMP/morph-t2-normal-20260922" --timeout 180
```

The actual runs used the worktree-specific Poetry venv's `python.exe` because
Poetry is managed through `uv tool run poetry`, not a global command. Roots are
exclusive; rerunning a fresh run against a nonempty root refuses to overwrite.

## T5 export contract

Read `events.jsonl` as full Envelope, `result.json` as TaskResult (including its
independent Acceptance dimensions), `genes.json` as `list[metabolism.models.GeneView]`,
and `adoption.json` as `list[metabolism.models.UseRecord]`. The existing three
example results correctly keep `contract_local=not_run` at individual task level;
the separate test suite provides contract_local evidence. Never infer it from a
successful model call. `summary.json` is diagnostic only; `execution_intents` is
an admission count, not proof that a provider actually billed a request. The
first observed summaries used `invocations` for this count; exact live call
counts above were also checked against real CLI thread/turn events.

  preserved real candidate files successfully, without another model call.
- The build gate for the full wheel remains integration/T0-owned until their
  package list update arrives; runtime source and live evidence are distinct
  from that release artifact.

- The public CLI does not expose a hard mid-call token/dollar cap. Token count is
  checked after completion and over-limit proposals are not applied. Dollar cost
  is unknown and remains `None`, never zero; unknown usage blocks automatic
  additional consumption. Three runs were explicitly authorized; there is no
  automatic next run. G0's hard cost/token budget requirement remains limited.
- No automatic model retry is implemented; provider/CLI internal transport
  behavior is upstream-owned. A killed/timed-out call has uncertain remote usage,
  and the persisted intent prevents blind re-execution.
- Read-only CLI plus proposal validation is the selected execution route; the
  verifier is a separate fixed local evaluator. Neither that evaluator nor the
  syntax gate is advertised as a general hostile-code security sandbox.
- Hub/remote provisioning/production and general multi-task scheduling were not
  run. Publication remains outside T2 ownership.
- Final packaging inclusion of `orchestration` is T0/integration-owned; the
  initial foundation wheel must not be mistaken for a full runtime distribution.
