## §1 新增决策：ORCA 无限量 Agent 批发（供给面）

### 1.1 决策内容
多 Agent 开发**可以利用 ORCA 进行无限量的 Agent 批发，数量没有上限**。

### 1.2 与此前"不依赖 ORCA"的消解（**两个不同维度，不矛盾**）

| 维度 | 结论 | 说明 |
|---|---|---|
| **代码 / 架构依赖** | **不依赖 ORCA** | 代码库独立自建，不做 ORCA 二开，不把 ORCA 当"地基"，不假设存在未声明的上游模块。 |
| **运行时 Agent 供给** | **可用 ORCA 批发，无数量上限** | ORCA 作为**运行时 Agent 供给面（provisioning plane）**，按需批量生成蜂群成员。 |

> **一句话**：**ORCA 是我们的"兵源"，不是我们的"地基"。** 此前"不依赖 ORCA"指的是代码地基；用户新澄清的是运行时兵源。二者可同时成立。

### 1.3 接入边界（四条，写入不变量）

1. **身份归一**：批发来的每个 Agent **必须获得本项目三层身份**（`Role`/`AgentId`/`AttemptId`）；ORCA 侧 ID 仅作**外部映射**，**不得替代内部身份**。
2. **单一所有者**：ORCA 适配层独立为 **`orca_provision/`**，与 `hub_client/` 同级，**归 T1 唯一所有者**；不得散落各轨。
3. **降级可用**：ORCA 不可用时，系统**降级为固定规模蜂群**，主闭环不受影响。
4. **不臆测**：ORCA 供给接口是**已声明接口**；任何轨道不得假设超出该接口的能力。

### 1.4 **"供给无上限" ≠ "支出无上限"**（关键护栏）

- ORCA 解除的是**蜂群规模上限**（可并行生成不限量成员）。
- 运行仍受《开发文档 v2》§10 **运行规格**约束：**总 Token/费用上限、每 `AttemptId` 最大重试、停止条件、文件权限、发布批准**。
- 二者并行：**规模维度放开，成本与副作用维度收紧。**
- 契约须新增 **`Provision` 记录**（供给来源、数量、配额、`provenance`），防止"无限扩张"失控、不可追溯。

### 3.2 身份与消息（不变量）
- 身份三层：`Role`（职责）/ `AgentId`（成员）/ `AttemptId`（尝试）——**缺一不可**。
- 消息统一 `Envelope`：`msg_id + msg_type + sender + receiver + task_id + attempt + artifact_uri + seq + handled + provenance + ts`。
- 供给记录：新增 `Provision`（ORCA 批发来源/数量/配额）。

### 3.3 门禁统一编号（**G0–G5**）

| 门禁 | 通过条件 | 时间锚点（参考） |

| **G1 契约冻结** | 一个调用方+一个实现方**跑通一次** | 9/22 14:00 起 |
| **G2 轨道集成** | 各轨在其目录内 `contract_local` 全绿 | 9/22 15:00 |
| **G3 真实接口** | T1/T2 达 `interface_live` | 9/22 22:00（T3 全绿） |
| **G4 端到端** | `interface_live` + `task_live` **分别**通过 | 9/23 01:00 |

### 3.4 隔离十维（全队强制执行）
文件系统（git worktree+独占分支）/ 契约（T0 独占+变更提案）/ 进程 / 端口（分配表）/ 数据存储（各轨独立 DB+索引）/ 消息事件（Envelope 去重）/ mock（provenance+三态）/ 凭据（各 worktree 独立 .env）/ 产物（内容寻址）/ 调度（合流门收敛）。

### 3.5 运行规格（含 ORCA 规模护栏）

| 项 | 要求 |
|---|---|
| 总预算 | 总 Token / 总费用上限，超限即停（**与 Agent 数量解耦**） |
| 最大重试 | 每 `AttemptId` 的重试上限 |
| 停止条件 | 达成 / 预算耗尽 / 无进展 N 轮 / 手动停止 |
| 文件权限 | 可写目录白名单，禁止越界写 |
| 发布批准 | 发布前人工/自动批准门 |
| **供给配额** | ORCA 批发需登记 `Provision`（数量/配额/来源），**规模放开但须可追溯** |
