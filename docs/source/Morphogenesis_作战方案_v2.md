## 二、主办方技术生态拆解

### 2.1 GEP 协议

**名称存在来源差异，不是拼写错误**：官方 Wiki 现用 **Genome Evolution Protocol**，相关论文使用 **Gene Evolution Protocol**。引用论文时保留其用词，接口实现以选定版本官方文档与 SDK 为准。

**资产类型不是三个，而是六类**。社区常说的「三件套（triple）」指 **Gene + Capsule + EvolutionEvent**：

| 对象 | 含义 |
|---|---|
| **Gene** | 可复用的策略模板（触发信号 + 摘要 + 策略 + AVOID + 验证） |
| **Capsule** | 某次真实执行的审计记录（含置信度、环境指纹、爆炸半径） |
| **EvolutionEvent** | 该轮进化的完整诊断上下文；类型名即 `EvolutionEvent` |

> **合规发布必须至少包含 Gene + Capsule**（经 `solidify` 自动发布时会一并链入 EvolutionEvent）。Skill 是重复成功后蒸馏出的可选第四类产物。
> 另：`Capsule` **不自动构成跨环境可复现保证**——须检查其包含的内容、环境与验证材料。

其他官方机制：内容寻址（SHA-256 生成 `asset_id`，用于去重与篡改检测）、置信衰减（**默认 30 天指数半衰期**）、低成功路径抑制、遗传漂移（以 `1/√gene_count` 概率从头部随机选而非选最优）。

> **重要修正**：衰减机制 **并非本项目首创**——GEP 已内建经验置信衰减与低成功路径抑制。「衰减」应表述为**对官方既有机制的适配**，不是新机制。

### 2.2 A2A + Swarm

- **Swarm 子 Agent 通信**：官方 Wiki 明确「**三种消息类型**支撑协作会话内的结构化协调」——`intent / result / signal`，端点 `POST /a2a/swarm/intent` 等。
- 但**不能把整个 A2A 体系限定为三种**：平台另提供结构化**对话消息** `challenge / agree / disagree / build_on`（用于挑战、同意、反驳、延展）。
- **审批是三种「策略」，不是三道连续审批**：`paranoid / supervised / autonomous`（端点 `POST /a2a/swarm/approval-strategy`），且**只能逐级升级**（paranoid → supervised → autonomous，禁止跳级），降级不受限，仅主节点可修改。
- 角色原型：builder / planner / reviewer（按能力信号匹配）。
- PDRI 循环（Plan–Do–Review–Iterate）。

> 本项目首版**采用** `intent / result / signal` 作为**最小消息集**；该选择不代表 EvoMap A2A 的全部消息类型。

### 2.3 「直连消息、共享工作区」的准确边界

原文表述过于简略：

- **Shared Workspace** 是基于 **R2/S3 的会话产物存储**，提供上传 / 列出 / 下载接口。**它不是让成员共享同一个本地可写目录，也不负责解决共同修改文件的冲突。**
- **「直连消息」** 应区分**逻辑上的成员定向通信** 与 **网络层不经中心服务的 P2P 连接**；本项目未提供后者的证据。

> 准确说法：成员可定向交流并共享产物，但传输、持久化与本地执行状态分别由对应服务管理。**共享产物 ≠ 共享可写文件系统。**

### 2.4 GDI（Genetic Desirability Index）

用于解释的**均值分数**与用于排名 / 自动晋升的**保守下界**是两回事。新鲜度按**最近活动**计算，而非仅看创建时间。GDI 是**综合排名指标，不是某条经验正确的概率**。

（若引用「质量 35% / 使用 30% / 社交 20% / 新鲜度 15%」的权重拆分，应注明其为**评分权重**。

> **关键澄清**：新鲜度占比是**评分权重，不是衰减速度**，**不能据此推算 Gene 的半衰期**。EvoMap 自身的经验置信衰减另有其默认参数（30 天半衰期）。本地经验池的遗忘策略与之是**两层不同机制**。

### 2.5 关于两个「EvoX」（重要更正）

前文把 IEEE TEVC 的 **GPU 加速进化计算框架 EvoX** 直接认作「EvoMap 生态」，并据此推导主办方学术背景与命名原因——**这一步缺乏一手证据**。

- 可核实：该框架为 **EMI-Group** 开源项目（arXiv:2301.12457），是面向分布式 / 异构 GPU 的进化计算框架，含 50+ 种单 / 多目标算法。
- EvoMap 语境中出现的「EvoX」指向其**自进化智能体 / 蜂群实验**一侧。
- **本轮未找到确认两者为同一项目、存在归属关系或命名关联的一手证据。**

> 正确表述：本项目参考 **EvoMap 的 EvoX 蜂群实验**；另有 **EMI-Group 开源的同名进化计算框架**，可作为外部算法工具参考；**目前未确认二者的组织或技术归属关系**。「主办方学术根基就是进化计算」「因此这些产品才如此命名」两句**予以删除**。

## 三、官方论文的实验发现及其适用边界

（原标题「硬结论」「结论直接决定评委审美」过度——「决定评委审美」是推测，非论文结果。）

相关报告为 **beta 技术报告**，研究的是 **45 个科学代码求解场景上的 4,590 次对照试验**（不是 4,590 个独立任务组），主要评价指标为**检查点通过率**，不等于完整任务成功率。

| 原表述 | 应补充的准确范围 |
|---|---|
| Gene `+3.0pp`，Skill `−1.1pp` | 两者均**相对于「无指导」基线**；不能理解为「Gene 比 Skill 高 3 个百分点」 |
| Gene 强于 Skill | 是**所报告条件下的总体平均**；**不是每个模型、每个任务都胜出**（报告的 Pro 模型在无指导与 Gene 条件下分别为 60.1% 与 59.9%，即未受益） |
| Gene 约 230 token | 是**实验中的典型表示长度**，不是协议规定长度，也不是已证明的最佳长度 |
| CritPt 两组提升 | 是**两个演化系统分别与各自配对底模**比较（9.1% → 18.57%；17.7% → 27.14%），**不是同一系统依次从 9.1% 长到 27.14%** |

可信的核心结论（原报告原意）：Procedural Skill 提供的控制信号稀疏且不稳定；**表示（representation）本身是一阶因素**；紧凑 Gene 表示在总体平均上最强、在结构扰动下仍具竞争力；**经验积累最有效的方式是选择性的、结构化的**——紧凑警告优于简单追加的失败历史。

> **本项目直接借鉴的**：把角色技能编码为约 230 token 级、面向「测试时控制」的 Gene 对象，并采用「选择性压缩而非加法式累积」的经验管理原则。此为**设计取向**，不主张复现论文的全部结论。

## 四、生物机制迁移

**每个机制必须回答一个冷酷问题：它省了什么 Token、提升了什么可测指标？** 回答不了的，砍掉。

| 生物原型 | 生物原理 | Agent 映射 | 得分点 | 证据强度 |
|---|---|---|---|---|
| 黏菌 | 管径随流量自适应增粗 / 萎缩 | 协作拓扑自组织生成与裁剪 | 结构涌现 + Token 节流 | 借用思想，**不继承收敛保证** |
| 白蚁 | 环境线索 / 间接协调 | 结构化「信息素」= 迷你 Gene | 去中心化叙事 | 机制假说存争议 |
| 代谢 | 物质转化与更新 | 经验整理 / 筛选 / 停用 | Token 效率 | **工程类比** |
| 进化 | 变异—选择—遗传 | 外层进化循环 | 前沿 + 复利故事 | 设计框架 |

### 4.1 黏菌（核心，但去掉过强承诺）

黏菌 *Physarum polycephalum* 的管流自适应最短路行为有实验与数学建模支撑（Tero 等；最短路收敛模型含 `Ḋ_e = |Q_e| − D_e`，其中 `Q_e` 由网络势差、边阻力和流量守恒共同决定，收敛定理另需固定图、正边长、初始正权重等条件）。Physarum 启发式也被用于求解 Steiner 树等 NP-hard 问题，但**报告的是可行解与误差，不保证全局最优**。

> **本项目表述**：采用**受黏菌「强化—衰减」思想启发的启发式权重更新**，**不直接继承**已有 Physarum 最短路模型的收敛定理，**不预先保证**最优拓扑或全局最优。
> 「最优协作拓扑自己长出来」「任意节点退出都能恢复」均为**待观察结果**，不作预设。

### 4.2 代谢 / 排泄（纠正概念混用）

- **代谢包含合成与分解，不等于排泄或废物清理。**「生物大部分能量花在代谢、清除废物更关乎生死」缺物种、条件与能量核算口径，删除。
- 「经验合并＝自噬」「经验归档＝凋亡」**只能作为工程类比，不能写成生物学一一对应**。

> 正确表述：借用代谢中的**转化、更新与物质循环**作为设计类比，映射为**经验整理、筛选和停用**。该映射是工程抽象，不是对细胞代谢、自噬或凋亡机制的直接复现。

### 4.3 白蚁（限定机制）

「信息素泥球建造」不宜写成唯一确定机制。相关研究对具体刺激仍有讨论，2024 年一项实验在其条件下支持**几何、基质蒸发等环境线索**的作用，并指出「建筑信息素」的直接证据尚不充分（**不证明信息素无关，但足以说明原表述过于单一**）。

> 正确表述：借鉴白蚁**通过建筑材料与环境线索进行间接协调**的机制，不将特定信息素假说作为唯一已确认解释。

`stigmergy-scheduler`（PyPI，2026-03-27 发布）记录属实，可保留。「别人的信息素只有标量、我们首次加入结构化语义」**缺少系统比较，不宣称首创**。

### 4.4 进化（外层框架）

「形态发生」与「跨代进化」需**分开定义**：一次运行中组织结构改变，**不自动等于**发生了遗传与选择。

## 五、耦合架构

### 5.1 命名：Morphogenesis（形态发生）

标注为**思想借鉴**而非理论继承：反应—扩散、黏菌管流适应与间接协作**分别提供不同启发，不视为同一个数学机制**。图灵 1952 年论文核心是**反应—扩散系统如何形成空间模式**，不是「有化学梯度就能自组织」，**不将其作为黏菌与白蚁机制的统一理论根基**。

（生物学修辞不承担科学论证作用。）

### 5.2 三层架构

```
┌─────────────────────────────────────────────┐
│  外层 · 进化循环（本项目目标函数驱动）         │
│  种群 = 蜂群配置（拓扑/角色配比/Gene 组合/审批）│
│  目标函数 = 本项目拟定（见 5.3，非官方公式）    │
└───────────────────┬─────────────────────────┘
                    │ 解码为蜂群配置
┌───────────────────▼─────────────────────────┐
│  内层 · 协作拓扑（黏菌启发式权重更新）         │
│  已有链路 = 带权边；成功流量增粗，闲置衰减      │
│  planner / builder / reviewer / aggregator    │
│  消息走 intent / result / signal 最小集        │
└───────────────────┬─────────────────────────┘
                    │ 执行中消费/产出 Gene
┌───────────────────▼─────────────────────────┐
│  代谢 · 经验整理（工程类比）                  │
│  新经验 → 蒸馏为紧凑 Gene；置信衰减（适配官方） │
│  低价值经验进入合并候选 / 归档停用            │
└───────────────────┬─────────────────────────┘
                    │ 最优 Gene 发布
┌───────────────────▼─────────────────────────┐
│  EvoMap Hub（须本地验证 → Gene+Capsule 打包）  │
└─────────────────────────────────────────────┘
```

> **对齐注（9/22）**：上图中「外层·进化循环」为**可选扩展**，不阻塞主闭环；主链以内层拓扑 + 代谢先行（详见《统一对齐与矛盾消解说明》C13 与 T4 出主链）。

### 5.3 外层目标函数（标注为本项目拟定）

官方 Group Evolution 给出 `performance × √novelty`（performance 关联任务成功率与 GDI 加权声誉，novelty 基于能力向量近邻距离）。本项目若改为 **`完成度 × √新颖度 ÷ Token 开销`**，则**同时改变了指标含义并加入成本项**，必须标注为**本项目拟定目标函数**。

它存在一个**直接的目标偏差**（假设新颖度相同）：

- 完成度 0.5、消耗 100 Token → 0.005
- 完成度 1.0、消耗 1000 Token → 0.001

→ 公式可能**偏好「便宜但没完成」**的方案。若不接受，应**先满足硬验收，再比较成本**。另需定义：新颖度相对于谁、各量如何归一化、失败与评估调用是否计入成本、分母为零如何处理。

### 5.4 「去中心化」需要说清楚

存在 planner 不自动否定去中心化，但也不能仅凭「有多个 Agent」就确认去中心化。应分别说明：**谁分配任务、谁持有权威状态、谁批准最终结果、谁选择下一代配置**，其中哪些集中、哪些局部决策。

还需区分**任务依赖图**与**通信偏好图**：不常用的通信关系可以降权，但「必须经过独立复核」的**依赖不能因流量低而被裁掉**。

### 5.5 审批策略不能作为普通可变「基因」

若把审批策略放入配置染色体自由优化，搜索可能**通过减少复核提高分数，而非真正提升能力**。

> 边界：权限上限、必要验收与不可豁免的安全检查属**可行性约束，不由适应度优化解除**；审批策略只能在用户授权及平台允许范围内调整。外层修改 Gene / 角色 / 拓扑时**必须保存对应配置版本**，否则一条效果曲线无法说明是哪项改变起了作用。

## 六、必背公式（机制审查防线，含修正）

### 6.1 管道权重更新（启发式，非定理）

```
D ← (1−λ)·D + α·Q·s
```

- λ 萎缩率（初始 0.05）、α 增粗率（初始 0.3）、Q 流量、s 成功率。
- **这两个参数是本项目初始超参数，不是官方推荐值或生物常数。**

**可直接推导出三个限制（必须在实现中显式处理）：**

1. **恒定输入收敛到的是权重值，不是「最优拓扑」。** 令 `Q·s = r` 为常数且 `0<λ<1`，则 `D_t = (1−λ)^t·D_0 + (αr/λ)[1−(1−λ)^t] → αr/λ`。只说明递推稳定，**不能证明组织最优**；输入随任务变化时结论需重新分析。
2. **闲置链路不会在有限轮数内自动消失。** 当 `r = 0`，`D_t = (1−λ)^t·D_0`，只要初始值 > 0，有限步内仍 > 0。**要「删除链路」，必须额外规定阈值、连续低活跃窗口和保留条件。**
3. **更新已有边不会自动产生不存在的边。** 需定义候选连接如何出现、何时尝试、失败后如何恢复，否则实现的只是「已有连接的权重调整」，不是完整的「拓扑自组织生长」。

> 需明确：更新频率、Q 的统计口径、s 的估计窗口、权重上限、裁剪规则、新边生成规则。

### 6.2 经验衰减（参数含义修正）

原式 `w(t) = w₀·e^(−t/τ)` **把 τ 称为半衰期是错误的**：代入 `t = τ` 得 `e^(−1) ≈ 36.8%`，不是 50%。**τ 是时间常数。**

两种正确写法（任选其一保持一致）：

- 保留原式并改解释：`t_{1/2} = τ·ln2`
- 或直接以半衰期 h 表示：**`w(t) = w₀ · 2^(−t/h)`**

> 还必须说明 **t 从创建、最近使用还是最近验证开始计算，以及时间单位**，否则不同实现结果不同。

### 6.3 经验合并（去掉「自动升级」）

「同主题 ≥3 条弱 Gene 且平均置信度低 → 合并为强 Gene」**不是成立的算法结论**：低置信度可能表示**证据不足、内容冲突或环境不适用**，三种情况不适合同一种合并方式；合并也可能生成一条更流畅但仍错误的策略。

> 正确做法：同主题经验可**触发合并候选生成**；生成后**核对来源、适用条件、冲突与验证结果**，再决定采用、保留分支或拒绝。**未经验证的合并结果不得自动升级为高置信经验。**

## 七、接入 EvoMap Hub（修正最小发布流程）

**不是「发布单条 Gene」**，而是**本地验证 → 构造 Gene + Capsule 打包 → 计算资产哈希 → 认证发布 → 检查回执与状态 → 确认可发现性 → 由另一节点获取、适配并验证**。

关键点：

- 合规发布**至少须包含 Gene + Capsule**；客户端先构造资产与 `asset_id`，Hub 复算校验。
- 存在**状态生命周期**（如 `candidate → promoted`）；接受后进入 `candidate`，**不是立刻对所有查询可见**。标准 `fetch` 返回的是符合条件的 **promoted** 资产；取得内容后**仍需在本地适配验证**。
- `hello` 方向正确（注册节点、取得 `node_secret`），但**秘密为「如签发则应保存」**；首次注册或明确轮换才返回，**不能假设每次 `hello` 都重新返回**。另有 `claim_code` / `claim_url` 用于绑定账户。
- **SHA-256 只核对内容身份与完整性，不能证明内容正确、来源可信或已执行成功。**

> 因此「发布成功 / 被获取 / 被采用 / 复用成功」**必须分别记录**。「一个蜂群学会，全场蜂群继承」只能作为**愿景**，不预先写成事实。

## 八、故障恢复（纠正归因）

「管道重路由」**不能推出**「任意节点退出都能恢复」。找到新接收者只解决「交给谁」，**没有解决「从哪里继续」**。

恢复还依赖：任务是否有稳定身份、已有产物是否保存、旧执行者是否仍在写入、哪些副作用已发生、重试是否会重复操作。

> 正确表述：网络路由机制负责**选择替代成员**；任务恢复依赖**独立的检查点、执行身份、状态核对与重复操作控制**。恢复成功需同时满足**状态接续与最终验收**，不能仅用「图上流量迁移」判定。「成功率短暂回落几轮后恢复」应改为**待观察结果**，而非预设轨迹。

## 十一、评委追问快答（睡前背 · 已按核查更新）

**Q：管道更新公式？**
`D ← (1−λ)·D + α·Q·s`，λ≈0.05、α≈0.3、Q 流量、s 成功率，为**本项目初始超参数**。须注意三点：恒定输入只收敛到权重值（`→ αr/λ`），**不等于最优拓扑**；闲置链路须靠**阈值 + 低活跃窗口 + 保留条件**显式裁剪，否则有限步内不归零；**更新已有边不会自动生成新边**，新边候选规则须另行定义。

**Q：Gene 和普通 Prompt 有什么区别？**
Gene 是约 230 token 级的**控制型对象**：匹配信号 + 摘要 + 有序策略 + AVOID。官方 beta 报告在 45 个科学代码场景、4,590 次对照试验中观察到：**表示本身是一阶因素**；相对「无指导」基线 Gene 平均 +3.0pp、文档型 Skill 平均 −1.1pp（且**并非每个模型都受益**）。差别在**表示的取向**——面向模型控制，而非面向人阅读。

**Q：为什么做衰减 / 清理？**
活性池保持精瘦有助于控制注入 Token。但**衰减不是本项目首创**：GEP 已内建经验置信衰减（默认 30 天半衰期）与低成功路径抑制。本项目是**在官方机制之上的适配**。且「同主题经验合并」**不自动产出高置信结论**——须核对来源、适用条件与冲突后再决定采用或保留分支。

**Q：如何接 EvoMap？**
流程为：本地验证 → 构造 **Gene + Capsule** 打包 → 计算资产哈希 → 认证发布 → 资产进入 `candidate` → 复核后 `promoted` → **另一节点 fetch、本地适配并验证**。「发布成功」「可被发现」「被获取」「复用成功」分别记录；内容哈希只保证完整性，不保证正确性。

**Q：节点挂了怎么办？**
网络路由负责**选择替代成员**；真正的恢复依赖**检查点、执行身份、状态核对、副作用控制与重复操作防护**。恢复成功需同时满足**状态接续与最终验收**，不能仅凭「图上流量迁移」判定。能否恢复是**待验证结果**。

**Q：和 AutoGen / MetaGPT 有什么区别？**
**不能概括为「它们都是静态的」**——例如 AutoGen 官方的 `SelectorGroupChat` 已支持依据上下文**动态选择下一位成员**。本项目的差异应落到**具体机制与所比较的配置**：拟在固定角色链与动态成员选择之外，进一步研究**基于历史反馈的连接权重调整**与**经验版本继承**。

## 十二、防坑三条

**① 别全都要。** 黏菌拓扑 + 经验整理是核心，白蚁已内化，进化作外层框架。48 小时**做深两个机制**远胜浅做四个——评审看代码时，「每个机制都有公式、参数和边界」比「提到很多生物名词」值钱。

**② 每个隐喻过「机制审查」。** 进化计算背景的评委对「装饰性隐喻」免疫，对「机制级映射」敏感。三个公式必须钉死，**并主动交出边界**（收敛不保证、τ 非半衰期、合并不自动升级）。

**③ 生物学放解释层，不放开场。** 先让评委看到系统在跑、指标在动，再揭示生物学对应物；顺序反过来像生物课。
