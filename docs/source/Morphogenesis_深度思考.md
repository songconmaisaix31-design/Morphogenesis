## §1 核心命题：壳与幽灵

主题是《攻壳机动队》。我们把这个词拆成可工程化的两半：

- **壳（Ghost in the Shell 的"Shell"）** = Agent 实例 + 消息协议 + 管道拓扑。**是可见、可枚举、可被代码审查的部分。**
- **幽灵（Ghost）** = 涌现出的、**不属于任何单个 Agent 的集体策略**。它没有独立宿主，只存在于"成员之间的关系与历史"里。

**深度思考的起点**：如何让"幽灵"成为**可观测、可复现、可被外部继承**的东西，而不是一句玄学？

我们的答案分三步推理：

1. 幽灵要"看得见" → 集体策略必须被**外化为对象**（Gene：可读、可哈希、可发布、可被别的蜂群继承）。
2. 幽灵要"长得出来" → 结构与策略不能由人预先写死，必须由**历史反馈自组织**（黏菌式权重、经验选择）。
3. 幽灵要"活着" → 系统必须**自我代谢**（新经验蒸馏、弱经验衰减、无效经验归档），否则经验池只会膨胀、稀释控制信号。

> 一句话：**壳是我们造的那部分，幽灵是系统自己长出来的那部分。评审看的不是壳多漂亮，而是幽灵是否真的涌现且可被检验。**

## §2 生物学迁移的方法论

### 2.0 每个机制先过"机制审查四问"

在把任何生物学概念写进架构前，先冷酷地回答：

1. **它省了什么 Token？**
2. **它提升了什么可测指标？**
3. **它对应哪个工程机制（而非修辞）？**
4. **它有哪些不能承诺的边界？**

四问答不全的，**只作为叙事，不进主链**。这条纪律直接决定了 §2.1–2.4 的分级。

### 2.1 黏菌（Physarum）——借用"思想"，不继承"定理"

- **生物原理**：管径随流量自适应增粗/萎缩，网络自组织趋近高效拓扑（Tero 等；最短路收敛模型含 `Ḋ_e = |Q_e| − D_e`）。
- **我们的映射**：协作链路 = 带权边，成功流量增粗、闲置衰减，**拓扑自己长出来**。
- **深度思考（关键取舍）**：收敛定理的成立需要固定图、正边长、初始正权重等条件，**我们的场景不满足**（任务在变、图在长、边会生会灭）。因此——
  > 采用**受黏菌"强化—衰减"思想启发的启发式权重更新**，**不直接继承**已有模型的收敛定理，**不预先保证**最优拓扑。

这是全篇最重要的一个"敢写局限"的示范：**借思想可以，借结论需要条件。**

### 2.2 白蚁——stigmergy 已"内化"，不再单列机制

- **生物原理**：通过建筑材料与环境线索进行间接协调（stigmergy）。注意 2024 年实验在其条件下支持"几何、基质蒸发等环境线索"的作用，**"建筑信息素"的直接证据尚不充分**——所以不把某一种信息素假说当唯一解释。
- **我们的映射**：**白蚁的间接协调思想已被内化为"管道权重 + 迷你 Gene 信息素"两层**，不再单独占用一个机制模块。

> 深度思考：**能合并的隐喻就合并**。48 小时做深两个机制，远胜浅做四个。白蚁在这里的角色是"叙事佐证"，不是"独立算法"。

### 2.3 代谢——工程类比，不是细胞复现

- **概念纠偏**：**代谢包含合成与分解，不等于排泄或废物清理**。"经验合并=自噬""经验归档=凋亡"**只能作为工程类比**。
- **我们的映射**：借用代谢的**转化、更新与物质循环**，映射为**经验整理、筛选、停用**。
- **深度思考**：为什么需要"代谢"而非只做"积累"？因为控制信号的信噪比问题——**官方结论：经验积累最有效的方式是选择性的、结构化的；失效经验堆积会稀释控制信号**。所以"代谢"不是美学，是 Token 效率的工程刚需。

### 2.4 进化——把"形态发生"与"跨代进化"分开定义

- **形态发生（Morphogenesis）**：**一次运行中**组织结构改变（拓扑生长/裁剪）。
- **跨代进化**：配置/策略的变异—选择—遗传（外层循环）。
- **深度思考**：一次运行里组织变化，**不自动等于**发生了遗传与选择。把两者混为一谈，会让"进化"变成无法证伪的叙事。分开定义后，各自有独立的验证指标。

### 2.5 命名与理论根基的诚实

"Morphogenesis / 反应—扩散"是**思想借鉴**：反应—扩散、黏菌管流适应、间接协作**分别提供不同启发，不视为同一个数学机制**。图灵 1952 年论的是"反应—扩散如何形成空间模式"，**不作为黏菌与白蚁机制的统一理论根基**。

## §3 三层架构的推理链

```
外层 · 进化循环        种群 = 蜂群配置（拓扑/角色配比/Gene组合/审批上限）
      │ 解码为蜂群配置       目标函数 = 本项目拟定（非官方公式）
      ▼
内层 · 协作拓扑        已有链路 = 带权边；成功增粗 / 闲置衰减
      │ 执行中消费/产出 Gene  planner / builder / reviewer / aggregator
      ▼                     消息走 intent / result / signal 最小集
代谢 · 经验整理        新经验 → 蒸馏为紧凑 Gene；置信衰减（适配官方）
      │ 最优 Gene 发布       低价值经验 → 合并候选 / 归档停用
      ▼
EvoMap Hub（本地验证 → Gene + Capsule 打包 → 发布）
```

**推理链（为什么是这三层，而不是别的）：**

| 层 | 回答的问题 | 若缺失会怎样 |
|---|---|---|
| 外层进化 | "**哪种组织结构更好**" | 只有单点配置，无法回答"换个分工会不会更好" |
| 内层拓扑 | "**在当前结构里，谁和谁的协作该被强化**" | 协作关系写死，幽灵无从涌现 |
| 代谢 | "**学到的经验如何被保留/淘汰**" | 经验池单调膨胀，注入 Token 失控 |

> **闭环的必要条件**：三层必须**串成一条数据流**——外层产出配置 → 内层按配置运行并把"真实成功/失败"回写 → 代谢据此更新经验 → 最优经验发布并回流为新一代配置的候选。**任何一层断开，系统就退化为"一堆 Agent 在跑"，而不是"一个会进化的生命体"。**

## §4 三个公式的深度思考（推导 + 必须显式处理的边界）

### 4.1 管道权重更新

```
D ← (1−λ)·D + α·Q·s        λ 萎缩(初始0.05) · α 增粗(初始0.3) · Q 流量 · s 成功率
```

**为什么是这个形式**：它是一个"指数遗忘 + 流量加权正反馈"的递推。**λ 提供遗忘，α·Q·s 提供强化**，正反馈使高频高质链路自动加粗。

**深度思考——三条必须写进代码的边界（否则实现的是"半个系统"）：**

1. **恒定输入收敛到的是权重值，不是"最优拓扑"。** 令 `Q·s=r` 常数、`0<λ<1`，则 `D_t = (1−λ)^t·D_0 + (αr/λ)[1−(1−λ)^t] → αr/λ`。**只证明递推稳定，不证明组织最优。**
2. **闲置链路不会在有限轮内自动归零。** `r=0` 时 `D_t=(1−λ)^t·D_0`，只要初值>0，有限步仍>0。要"删除链路"，**必须额外规定阈值 + 连续低活跃窗口 + 保留条件**。
3. **更新已有边不会自动生出新边。** 必须定义**候选连接如何出现、何时尝试、失败如何恢复**——否则做的是"权值调整"，不是"拓扑生长"。

> **这就是"机制级映射"与"装饰性隐喻"的分水岭**：我们主动交出这三条限制，而不是宣称"最优拓扑自己长出来"。

### 4.2 经验衰减（参数含义纠错）

原式 `w(t) = w₀·e^(−t/τ)`。**把 τ 叫"半衰期"是错的**：代入 `t=τ` 得 `e^(−1)≈36.8%`，不是 50%。**τ 是时间常数。**

两种正确写法（任选其一并保持一致）：
- 保留原式并改解释：`t_{1/2} = τ·ln2`
- 或直接以半衰期 h 表示：`w(t) = w₀ · 2^(−t/h)`

**并必须说明**：`t` 从创建、最近使用还是最近验证起算，以及时间单位——否则不同实现结果不同。

> 另需澄清：**EvoMap 官方 GEP 已内建经验置信衰减（默认 30 天半衰期）与低成功路径抑制**。"衰减"应表述为**对官方既有机制的适配**，不是本项目首创。GDI 中的"新鲜度"是**评分权重**，**不是衰减速度**，不能据此推算半衰期。

### 4.3 经验合并（去掉"自动升级"）

"同主题 ≥3 条弱 Gene 且平均置信度低 → 合并为强 Gene"**不是成立的算法结论**：低置信度可能表示**证据不足 / 内容冲突 / 环境不适用**，三种情况不适合同一种合并方式；合并也可能生成一条"更流畅但仍错误"的策略。

> 正确做法：同主题经验**触发"合并候选生成"**；生成后**核对来源、适用条件、冲突与验证结果**，再决定采用 / 保留分支 / 拒绝。**未经验证的合并结果不得自动升级为高置信经验。**

## §5 从生物隐喻到工程契约：三处最容易"做成装饰"的地方

生物学叙事最容易"听起来很美、代码里没有"。我们用三处契约把它钉死：

### 5.1 身份三层（否则"分群"无法落地）

`Role` 只表示**职责**，无法区分 3 个 builder。修正为：

```
Role（职责: planner/builder/reviewer/aggregator）
  └─ AgentId（成员实例: role + instance 序号）
       └─ AttemptId（执行尝试: task_id + agent + attempt）
```

**规则**：路由可先选 Role 再选实例，也可直接选实例——**但不得省略实例层**。实例级执行必须单独记录，Role 级统计只作**聚合视图**。

> 深度思考：**"幽灵不属于任何单个 Agent"，前提是系统能分清"哪个具体 Agent"。** 分不清个体，就谈不上"集体"。

### 5.2 消息成封装（否则协作不可追溯）

三个枚举不够。定义**统一封装**（呼应 `gep-a2a` 的 7 必填字段思想）：

```
Envelope = msg_id(幂等键) + msg_type + sender + receiver + task_id
         + attempt(AttemptId) + artifact_uri + seq + handled
         + provenance(live|replay|mock) + ts
```

**能回答**：谁在什么任务的哪次尝试中，向谁发送了什么，关联了哪个产物，是否已处理。

### 5.3 经验所有权矩阵（否则多管理者打架）

| 问题 | 唯一所有者 |
|---|---|
| 谁拥有经验正文 | Evolver 记忆图（本地）+ Hub（远端）；本地 `Gene` 正文由 `metabolism` 缓存 |
| 谁维护本地使用状态 | `metabolism`（`mark_used` / 衰减） |
| 谁决定停用 | `metabolism`（`archive`），**停用须原子地清除检索索引** |
| 谁产生候选 | `evolution`（配置候选）/ `metabolism`（合并候选） |
| 谁最终发布 | T1 HubClient，**须过发布批准门**；Evolver 不得按自身阈值自动发布 |

> 一致性约束：归档/停用必须**原子同步**记忆图、本地缓存、检索索引三处，否则会出现"已归档仍被检索"。

## §6 为什么会"自我代谢与进化"——闭环成立的判据

我们不用"它会进化"来收尾，而用**可检验的判据**：

- [ ] **权重真的影响调用**：改权重后下一次选路结果随之改变。
- [ ] **重复结果不重复奖励**：同一 `msg_id`/`attempt` 重复上报，权重只更新一次。
- [ ] **接续不重复副作用**：恢复后无重复文件写入/重复工具调用。
- [ ] **经验真的被使用**：`inject` 后的 Gene 在运行中留有 `mark_used` 记录。
- [ ] **模拟不冒充实测**：`provenance=mock` 的结果不进入 `task_live` 验收。
- [ ] **三态验收分离**：`contract_local / interface_live / task_live` 各自独立。

> 深度思考：**"自我代谢与进化"是可证伪的工程命题，不是标语。** 上面的勾选都能独立跑，且**任何一条用 mock 通过都不算数**。

## §8 独立原型边界：ORCA 的定位（开发独立性 vs 运行时供给）

**最新澄清（用户 9/22）**：多 Agent 开发**可以利用 ORCA 进行无限量的 Agent 批发，数量没有上限**。这与此前"不依赖 ORCA"并不矛盾——**两者是不同维度**：

| 维度 | 结论 |
|---|---|
| **代码 / 架构依赖** | **不依赖、不派生自 ORCA**：代码库独立自建，不做"二开"，不假设存在未声明的上游模块。 |
| **运行时 Agent 供给** | **可用 ORCA 批发 Agent，数量无上限**：ORCA 作为**运行时供给面**，按需批量生成蜂群成员。 |

> 一句话：**ORCA 是我们的"兵源"，不是我们的"地基"。** 代码自建（不被 ORCA 绑定），蜂群规模可借 ORCA 无限扩张。

据此，此前开发文档 §5.1 挂起的"架构边界"问题**闭环**。四条硬边界更新为：

1. **无上游继承**：Morphogenesis **不派生自 ORCA 或任何既有工程**，不加"二开"外壳；所有模块按本方案自建。
2. **执行宿主自持**：执行入口**三选一后固定**（① 模型 API + 自定义 loop ② 现有 CLI ③ 自建最小宿主），**不假定**某个既有工程的执行宿主/工具层。选定后写入《执行入口说明》。
3. **契约自洽**：三层身份、统一 Envelope、经验所有权矩阵**由本项目定义并冻结（以"调用方+实现方跑通一次"为准）**，不与外部工程做兼容性妥协。
4. **不臆测上游结构**：禁止任何轨道假设存在未声明的上游代码；本项目对外只有两个**已声明**稳定接口——**EvoMap A2A/GEP（MCP 主路径，经验侧）** 与 **ORCA Agent 批发接口（供给侧，可选）**。
5. **供给无上限 ≠ 支出无上限**：ORCA 可批发不限量 Agent，但运行仍受运行规格（总预算 / 最大重试 / 停止条件）约束；规模可无限扩，成本与副作用必须有护栏，并登记 `Provision`（来源/数量/配额）。

> **深度思考**：把 ORCA 限定为"运行时兵源"、不放进"代码地基"，**既消除了不可控的上游耦合，又拿到了无限扩张蜂群的能力**——每一个能跑起来的环节，仍是我们自己能解释、能被 Review 的环节。这恰好契合"评审团特别奖：代码经得起巡场 Review"的取向。

**仍待确认（不阻塞开工）**：EvoMap Hub 的**沙箱地址与凭据**。确认前，发布链路**只能使用本地隔离 stub**，**禁止向生产平台发布虚构结果**；Hub 不可用时产品显示"**待发布**"并保留本地产物。

## §10 一句话思想总结

> **壳，是我们造的那些 Agent、协议与管道；幽灵，是它们之间的历史流量自己长出的、不属于任何单个 Agent 的集体策略。**
> 我们不"设计"幽灵，我们只提供**能长出幽灵的代谢条件**——可观测、可检验、可被外部继承，且**独立于任何既有工程**。
