- **被测版本**：Morphogenesis `0.2.1`
- **评测套件**：MorphBench（已改造：MorphSwarm 改走真实 swarm 模块）
- **运行日期**：2026-10-07
- **环境**：项目 `.venv`（Python 3.13）· numpy 2.5.3 · scikit-learn 1.9.1 · 纯 CPU
- **命令**：`PYTHONPATH=<repo> python run_demo.py --budget {24|8} --seed 0 --out ...`
- **产出**：`outputs_real/`（预算 24，5m41s）、`outputs_real_b8/`（预算 8）、`outputs_surrogate_b8/`（重实现对照）

> **一句话结论**：真实引擎接上了，并且第一次和"重实现"拉开了差距
> —— 预算 8 下 **MorphSwarm 87.29 > 中心调度器 86.79 > 单智能体 85.86**，

> 但请务必读完第六节：这套数字**仍然不是**"0.2.1 在 BioML-Bench 上的分数"。

## 一、做了什么：真实引擎是怎么接进去的

新增 `morphbench/real_swarm.py`，把实验分配权交给 0.2.1 自己的模块：

| 用到的真实模块 | 承担的角色 |
|---|---|
| `swarm.task_ledger.TaskLedger` | 每个候选配置 = 一个真实任务；`enqueue` / `claim`（fencing token）/ `submit`。"不做重复功"来自账本自身的 eligibility 规则，**不是** Python `set` |
| `swarm.pheromone.PheromoneField` | 结果沉积 + `metabolism.decay.exponential_decay` 指数衰减；每步按浓度物化候选 |
| `swarm.router.Router` | 按 `浓度 × pipe_history × urgency` 做 softmax 加权采样选下一个实验；`reinforce` 回写学习 |
| `swarm.models` | `Signal` / `Locality` / `TaskRecord` / `RunLimits` / `Lease` |

**属于评测侧胶水（我们的策略，不是引擎行为）**，已在代码注释里明确标注：
配置 → Signal 的编码与 x/y 坐标、沉积量、邻域半径与上限、`tau_seconds=30`（默认 86400 在 2 分钟跑里等于不衰减）、`exploration=0.10`、经验如何跨轮继承（复制 pheromone DB）。

设 `MORPHBENCH_SURROGATE=1` 可切回原重实现，做同口径对照。

## 二、结果 A：预算 8（区分度预算，主结果）

预算 8 < 最小搜索空间 9，任何策略都无法穷举，分配策略才真正起作用。

| 系统 | 平均排行榜百分位 | 完成率 | 平均冗余率 |
|---|---|---|---|
| SingleAgent | 85.86 | 1.0 | 0.275 |
| CentralScheduler | 86.79 | 1.0 | 0.000 |
| **MorphSwarm（真实引擎）** | **87.29** | 1.0 | **0.000** |

逐任务（验证分 / 百分位 / 重复单元）：

| 任务 | SingleAgent | CentralScheduler | MorphSwarm |
|---|---|---|---|
| BM-01 蛋白质适应度回归 | 0.7359 / 90.52 / 2 | 0.7829 / 95.15 / 0 | **0.8199 / 96.02 / 0** |
| BM-02 ADMET 分类 | 0.9695 / 98.00 / 3 | 0.9866 / 98.00 / 0 | 0.9866 / 98.00 / 0 |
| BM-03 单细胞注释 | 0.9107 / 92.78 / 3 | 0.9107 / 92.78 / 0 | **0.9345 / 94.44 / 0** |
| BM-04 生物医学图像 | 1.0000 / 98.00 / 3 | 1.0000 / 98.00 / 0 | 1.0000 / 98.00 / 0 |
| BM-05 GPT 超参优化 | −1.1268 / 50.00 / 0 | −1.1268 / 50.00 / 0 | **−1.0521 / 50.00 / 0** |

真实引擎在 BM-01 / BM-03 / BM-05 上拿到更好的配置；BM-02 / BM-04 三个系统都摸到空间最优（饱和）。

## 三、结果 B：预算 24（方案原定预算）

| 系统 | 平均排行榜百分位 | 完成率 | 平均冗余率 |
|---|---|---|---|
| SingleAgent | 87.12 | 1.0 | 0.4833 |
| CentralScheduler | 87.29 | 1.0 | 0.4250 |
| MorphSwarm | 87.29 | 1.0 | 0.4250 |

**这一组没有区分度，原因是套件的设计缺陷**：预算 24 大于 BM-01/02/03/04 的搜索空间（13 / 9 / 12 / 11 个配置），任何策略都会穷举完整个空间并拿到全局最优，剩余预算全是强制重复。
所以：
- 换成真实引擎后这一组数字**几乎没变**（不是没接上，是空间太小）；
- SB-04 冗余率 0.425 是预算产物，不是协调失败。

## 四、真实引擎 vs 套件自带重实现（同预算 8）

| 系统 | 真实 0.2.1 引擎 | 自带重实现 |
|---|---|---|
| SingleAgent | 85.86 | 85.86 |
| CentralScheduler | 86.79 | 86.79 |
| **MorphSwarm** | **87.29** | 86.79 |

重实现的 MorphSwarm 与中心调度器**逐任务完全相同**（去重逻辑与随机序列一致）。换成真实引擎后差距才出现——这是本次改动最直接的价值。

## 五、Tier A 机制指标（全部改为真实执行 / 实测）

| 指标 | 预算 8 | 预算 24 | 说明 |
|---|---|---|---|
| SB-01 swarm_survival | **1.0** | 1.0 | 杀 2 个 worker 后蜂群跑满预算 |
| SB-01 central_survival | **0.0** | 0.0 | 中心规划者被杀即停摆（10/20 单元） |
| SB-02 reuse_gain | **0.0** | 0.0 | 温场 9 单元 vs 冷场 9 单元，无差异 |
| SB-03 overhead_ratio | **4.2285** | 2.8632 | **实测墙钟**：1.87s→9.79s / 4.88s→18.87s |
| SB-04 redundant_rate | **0.0** | 0.425 | 预算 8 下真实账本零重复；24 系穷举所致 |

三项变化值得单独说：

1. **SB-01 现在是真跑出来的**：中心调度器在第 10 个单元被杀后真的停摆（`planner_alive=False` → 循环中断），蜂群跑满 20 个单元。不再是写死的 `1.0 / 0.0`。
2. **SB-02 从"恒等于 1.0"改成真测，结果是阴性的**：原版问的是"温账本能不能重新达到它已经记住的分数"——必然 100%。新版改成在同一空间的**扰动实例**上跑（记住的分数作废），携带的只有从第一轮复制过来的 pheromone + pipe history，目标是冷启动满预算能达到的质量。结果冷暖都是 9 单元，**增益 0.0**。这是个诚实的阴性结果。
3. **SB-03 从硬编码 0.15 改成实测，代价是真实偏高**：4.23×。原因见第六节。

## 六、仍然没有测到的东西（必读）

| # | 限制 | 影响 |
|---|---|---|
| 1 | **调度器真实，任务仍代理** | 87.29 不能读成"0.2.1 在 BioML-Bench 上 87 分"。五个 Tier B 任务仍是合成数据 + sklearn，换的是"谁来决定跑哪个实验" |
| 2 | **百分位锚点自造** | median/p75/p90/sota 是套件自己定的，不是公开排行榜分位数 → 不可与 AutoScientists 74.40% 比高低 |
| 3 | **BM-05 百分位锁死 50** | 该代理任务理论最优 −1.0521 劣于 median 锚点 −0.98，真实引擎在 BM-05 上的改进（−1.0521 vs −1.1268）在百分位上完全看不出来 |
| 4 | **SB-03 依赖单元成本** | 本次单元是廉价 sklearn 拟合（约 0.2s/次），协调开销占比被放大；若换成真实的 5 分钟 GPT 训练，4.23× 会大幅下降。这个数只能用于"同任务内"比较 |
| 5 | **单种子、无置信区间** | 全部 seed=0。0.5–1.4 个百分点的差距在 5 个小样本代理任务上**不具统计显著性** |
| 6 | **SingleAgent 仍是重实现** | 它没有对应的真实引擎形态（它是"无共享记忆"参照系），保持原样并在报告中标注 |
| 7 | **一步一 sqlite 事务** | 真实引擎每步约 10 次 sqlite 读写，这是 SB-03 偏高的直接原因，也是本套件的性能瓶颈 |

## 七、复现

```bash
# 真实引擎（默认）
PYTHONPATH=/path/to/Morphogenesis python run_demo.py --budget 8  --seed 0 --out ../outputs_real_b8
PYTHONPATH=/path/to/Morphogenesis python run_demo.py --budget 24 --seed 0 --out ../outputs_real

# 切回自带重实现做对照
MORPHBENCH_SURROGATE=1 python run_demo.py --budget 8 --seed 0 --out ../outputs_surrogate_b8
```

依赖：numpy / scikit-learn（`requirements.txt` 里的 pandas 代码未实际使用）。
